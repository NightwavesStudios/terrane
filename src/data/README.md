# Data files

`src/data/` mixes source fixtures, generated data and the app's typed model. Know
which is which before editing.

## Source (hand-maintained)

| File | What it is |
| --- | --- |
| `places.ts` | The typed atlas model and its type labels. `PLACES` is the generated atlas; reach pages use the generated page index. |
| `categories.json` | The one taxonomy: 16 destination categories in a single family. |
| `summits.ts` | The four sourced peakbagging lists, their club notes, source links and list membership. A listed peak may have a `place` slug; its coordinates live in the place record, never in the list. |
| `guide-selection.json` | The frozen editorial list of 183 curated Experience destination slugs. Membership changes here, not in the generator. |
| `guide.ts` | The curated Experience model: six kinds, hue hashing and the row/record types. |
| `bands.json` | Dot/label zooms, radius scale, opacity, label size and per-band grid quota. |
| `atlas-merges.json` | The documented duplicate merges that `validate` accepts. |
| `experience-sources.json` | The verified live status of every curated Experience article and Commons file page. The build and validator consume it offline. |

## Generated (commit the result when it changes)

| File | Generated by |
| --- | --- |
| `atlas.json` | the Wikidata atlas build |
| `reach.json`, `reach-more.json` | the Wikidata long-tail build |
| `wikidata-meta.json` | the two Wikidata pulls |
| `place-index/` | `scripts/build-place-index.mjs` (page records and slugs) |
| `place-details/`, `place-details-summary.json` | the Wikidata/Commons detail build |
| `guide-index/` | `scripts/build-guide.mjs` (catalog, 16 hash-bucket shards, meta; one curated destination per page, built only from its own details and photos) |
| `manifest.json` | `scripts/build-manifest.mjs`, then `validate-data.mjs` |

`manifest.json` is bundled into the app. It is deterministic: dates come from
`wikidata-meta.json` and the detail summary, never from the clock or checkout
mtimes. The validation block contains only the check results, no timestamp.

## Freeze rules

1. Every category must have at least one record, a known family and a colour.
2. No two destination rows in the same category may be within 50 m unless the
   pair is recorded in `atlas-merges.json` with the absorbed row in `also`.
3. `byCategory` and the total in the manifest must match the files; the build
   fails otherwise.
4. Every destination page has a page record and a detail record; every image has
   a credit and a licence. Every selected Experience slug resolves to a page, and
   every shipped source is `verified` in `experience-sources.json`.
5. Generated build output does not belong in git.

## Runtime versus bundled

The atlas, famous reach tail, manifest and categories are bundled. The rest of
the reach tail is a lazy chunk. A page loads one `place-index/` shard and one
`place-details/` shard for its slug; it never loads all 24,473 records. The
curated Experience list loads one compact catalog; an Experience page loads one
`guide-index/` shard. A listed summit without a place record is still a list row;
only the ones with a page record have a globe point.
